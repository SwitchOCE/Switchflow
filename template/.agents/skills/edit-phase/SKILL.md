# Edit Phase

Revise the named phase using `doc-09 - Scope-and-revisions.md` and its shared revision procedure. Read that document, `doc-03 - Kanban-workflow.md`, `doc-07 - Task-contract.md` under `backlog/docs/`, and the shaping rules in `plan-milestone`.

Read the current milestone revision, phase parent and prior records, complete affected tasks and owner comments, direct dependants and active assignments. Inspect repository areas needed to correct the plan; exclude the friction log.

Record the requested change and before-state on the phase parent. Distinguish a delivery adjustment from a changed outcome or UAT obligation. Route scope changes to `edit-milestone`; leave the accepted baseline intact while its proposal is unresolved.

Apply the shared procedure's active-work and fresh-state checks. Reuse planner rules to split, combine, sequence, relink or archive unstarted tasks. Preserve stable IDs where outcomes are unchanged, completed records, board-unique phase labels and valid evidence. Keep parent plan, native dependencies, groups, gate, context maps and affected UAT dependencies consistent.

Record progress on the parent after each material mutation and resume there after interruption. Ask the orchestrator to reassess changed In Progress or Review work; do not silently reset it or treat an old verdict as proof of new scope.

Read back changed records, run `doctor`, and report changes and reasons, current scope revision, worker queues, blockers and next authorized action. End when the plan is consistent; readiness does not dispatch workers or authorize another phase.
