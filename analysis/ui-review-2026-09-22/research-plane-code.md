# Plane Community Edition code review: human interaction appendix

## Scope and evidence boundary

This is a static review prepared 22 September 2026, of the public Plane Community Edition source pinned to
[v1.4.0 / `917b23a6c16d93fc00cef67900eff2755e8b13f7`](https://github.com/makeplane/plane/tree/917b23a6c16d93fc00cef67900eff2755e8b13f7) (release dated 31 July
2026).  The pin is a reproducible review target, **not** a claim that it is the current Plane
release.  I unpacked that tag locally and traced rendered callers and handlers. No Plane
instance was run, no API failure was injected, and no assistive technology test was performed.
Consequently every result below is **source-derived**, not runtime-verified; hosted/paid edition
behaviour may differ.

`KanBanLayout` is a live project route wrapper for `BaseKanBanRoot`, including the project-role
edit predicate ([caller](https://github.com/makeplane/plane/blob/917b23a6c16d93fc00cef67900eff2755e8b13f7/apps/web/core/components/issues/issue-layouts/kanban/roots/project-root.tsx#L17-L35)). This is why the Kanban observations below are not claims about an unreferenced component.

## Recommendations to carry forward

1. Convert Switchflow’s top navigation to an accessible sidebar that preserves the current board/task context, then restore focus to the opener when a detail view closes (P-C06).
2. Make the next actionable milestone/task visible as a dedicated, explainable callout; do not make people infer it from column position alone. Plane’s code supports orientation and safe transitions but does not itself solve prioritisation.
3. Keep empty columns as stable, appropriately sized, visibly highlighted drag targets during a drag; apply hide-empty only outside a drag and label the setting. Plane’s 120px minimum is an example, not a universal target (P-C02).
4. Replace the current always-before drop rule with above/below insertion feedback, target autoscroll, visible invalid-move reasons, and a post-drop highlight (P-C03–05).
5. Give task detail a resizable/full-screen reading mode, separated properties where space permits, and return the person to the originating card on close (P-C06–07).
6. Bound board and history rendering independently when volume warrants it: use incremental board access with a semantic “load more” button, and provide a deliberate route to older activity rather than relying on one page scroll (P-C01, P-C09).
7. Model absence, permission, archive, loading, saving, saved, and save-failed as visibly distinct states; retain retry/dirty state after any failed write (P-C08, P-C10).
8. Provide a keyboard-equivalent move/reorder path and semantic controls for every action. Plane’s reviewed group loader and filter option use click-only `div`s; copying them would carry an accessibility regression (P-C01, P-C09).

## Candidates deliberately not imported

- Plane’s fixed half-width, 5/6, and 400px values are layout choices, not standards; Switchflow needs responsive sizing against its actual content and viewport.
- Auto-load-on-scroll is not sufficient by itself: preserve a visible button and an item/result count so people know more history exists.
- A transient drag-to-delete target should not be the only deletion affordance, and deleting needs a confirmation plus a recovery story.
- The source does not prove an undo or rollback after failed drag persistence. Do not describe Plane as having one and do not use its error toast as a substitute.
