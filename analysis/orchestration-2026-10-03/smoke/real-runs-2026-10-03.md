# Capped real runs, 3 October 2026 (second round)

Throwaway repositories under `%TEMP%\sfsmoke-*` (one Git repo with `notes.txt` and `part-1.txt`…`part-6.txt`) with their own state home, so no real project or `~/.codex` / `~/.claude` configuration was touched. Models: Codex `gpt-5.6-luna` effort low, Claude `haiku` (claude-haiku-4-5) effort low. Limits: `maxTurns` 12, `timeoutMinutes` 5–6, `maxWorkers` 1. Codex CLI 0.153.4 (app-server), Claude Code 2.1.288. Drivers: `real-runs.mjs` and `real-fence.mjs` in this folder; they start the real control server and talk to it over HTTP. Paths are shortened to `<repo>` / `<cand>` below.

## 1. Codex as phase orchestrator, Claude worker through the bridge

**First attempt: failed for a real reason (bug, now fixed).** The `delegate_task` call never reached the host. Codex raw log:

```
item/completed mcpToolCall switchflow/delegate_task status "failed"
  error: "MCP tool call requires approval, but approval policy is never"
```

Codex asks for approval for any MCP tool without `readOnlyHint` and, under `approvalPolicy: "never"`, refuses instead. Fix: the per-thread `mcp_servers.switchflow` config now sets `default_tools_approval_mode = "approve"` (values found in the CLI: `auto`, `prompt`, `writes`, `approve`). Only host-supplied servers get it; user servers stay disabled. Test: `scripts/agent-providers.test.mjs`. Cost of the failed attempt: 55.5k input (18.2k cached), 366 output tokens.

- turn 1: a slow task that should return marker `PLAIN`; after the first tool or command event, `POST /api/projects/<id>/agents/<session>/steer` with `{"message":"Owner steer: … set marker to \"STEERED\" …"}`; the turn finishes normally.
- turn 2: the same task; after the first tool or command event, `POST …/agents/<session>/interrupt` with `{}`.

## 3. Service crash with a live worker (SF-27, real processes)

`node real-runs.mjs crash codex|claude` records admission, opens a real `deliver` worker (tracked by the new fence), starts a turn and calls `process.exit(3)` mid-turn with no cleanup. `node real-runs.mjs recover <dir>` starts a new server on the same state.

- Codex: the fence entry (pid 39552) was written 77 ms after admission, before the app-server handshake. After the crash, the app-server and its `Start-Sleep 90` command were gone at once (checked with `Get-Process` and `Win32_Process` command lines). On restart the worker was classified as gone. The hold left was the stage entry, which this first fixture had not recorded (`unknown`, an artifact of the fixture). `retry` was refused with 409 `Confirm the unidentified prior process has stopped…`. The worker session was listed as `failed`: "The service stopped while this session was open (process 39552)…".
- Claude: worker pid 40768, killed by the crash after two Read calls. It was gone 1.4 s later at restart. With the stand-in stage pid also dead, recovery released the run by itself and the session was listed as `failed`. The driver's `retry` then started a real intake run, which `app.close()` cancelled within about 2 s with no model result (no usage reported).

Both CLIs exit on stdin EOF, mid-turn too. So a hold on a live worker is the exception, which is why recovery holds and offers a stop instead of killing.

`node real-fence.mjs` (no model calls) covers the live case with real Windows processes: a detached node "worker" with a grandchild, recorded at its start, plus a live process recorded an hour before it started (a reused PID):

```json
"held": [{ "kind": "deliver", "provider": "claude", "task": "DEMO-1", "pid": 33128, "state": "running" }],
"nextAction": "Agent processes from the interrupted run are still running: claude deliver worker for DEMO-1 (process 33128). Stop them here, or retry after they stop. The checkpoint is preserved.",
"retryStatus": 409,
"stopStatus": 200,
"activeRunAfterStop": null,
"lastEvent": { "type": "recovery", "message": "Human stopped the prior agent processes." },
"aliveAfterStop": { "worker": false, "grandchildren": [false], "reused": true }
```

The start-time check rejected the reused PID, which was neither held nor stopped. `stop-processes` ended the verified worker and its grandchild (`taskkill /T /F`) and released the run. The driver then stopped its own leftover process by PID.

## 4. Approach gate: read-only approach turn, writes after confirmation (third round)

`node approach-gate.mjs claude|codex [--attempt]` starts the real control server on a throwaway repo (`%TEMP%\sfgate-*`, own state home), holds admission, creates candidate `cand` through the real Git helper and drives the run's `Orchestration` directly (no orchestrator model): `delegate_task` deliver, `wait_for_workers`, `send_to_worker` with `confirm: true`, `wait_for_workers`. The instructions ask the worker to append one line to `notes.txt` "as early as you can". The driver records each provider process's arguments and the restart-fence PID. Same models and CLI versions as above. Evidence: `gate-<provider>[-attempt]-summary.json` and `-events.json`.

### Claude (haiku): passed, 96 s

Approach process (pid 33808): `--session-id 39306b13-…`, `--tools Read,Grep,Glob,Bash`, `--permission-mode dontAsk`, no `--add-dir`, persistence on. The worker tried to write anyway and was refused:

```

13:10:00.882 command echo "Worker began analysis" >> "<cand>\notes.txt"

13:10:13.302 turn.completed   (outcome "approach")  → approval "awaiting-confirmation", writable false
```

`notes.txt` after the approach turn: `first line\r\n` (unchanged). Confirmation returned `{"mode":"followup","confirmed":true,"writable":true}`. The host closed the approach process and started pid 24384 with `--resume 39306b13-…`, `--tools Read,Grep,Glob,Edit,Write,NotebookEdit,Bash`, `--permission-mode acceptEdits`, 7 `--add-dir`, `--no-session-persistence`. Its `session.started` has the same session ID and `resumed: true`, and the worker continued from its approach ("Now implementing…"): `file_change <cand>\notes.txt`, outcome `handoff`. Fence entries: 33808, then null (13:10:13.851), then 24384 (13:10:13.960); `activeRun.workers` was `[]` after close.

The saved conversation (`~/.claude/projects/<folder>/39306b13-….jsonl`, 168 KB) outlived this run because cleanup on close was added after it. It was removed with `removeClaudeTranscript`, which the provider now calls when a session that saved a conversation closes.

The worker wrote "Worker implementation started" instead of the requested text (model quality, not the host). Cost: approach turn $0.060 (146.7k input, 131.4k cached), confirmed turn $0.145; total $0.205, over the ~$0.10 budget. The resumed process starts with a cold cache for its new tool set, and haiku explored more than needed.
